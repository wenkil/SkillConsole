# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

主要用户是需要在本地或自托管环境中开发、迭代和验证 Agent Skill 的开发者与 Skill 工程人员。他们需要在同一工作台内持续管理工作副本、正式版本、测试输入、执行任务和证据报告。

## Product Purpose

SkillConsole 将真实 Skill 源导入为长期存在的测试工作台，帮助用户完成“导入 Skill → 管理版本 → 生成测试用例 → 运行测试 → 阅读报告与证据”的闭环。成功意味着用户能快速判断当前状态、结果变化和下一步，同时仍可按需追溯完整技术证据。

## Positioning

SkillConsole 不是一次性运行器或通用文件管理器。它把 Skill 的工作副本、不可变版本、测试输入、执行记录和结果证据放进同一个可持续迭代的工作边界，并保持结果与技术证据之间的可追溯关系。

## Operating Context

- 桌面优先的专业工作台，当前最低布局宽度为 1024px。
- 支持简体中文与英文界面。
- Skill 源文件复制到服务控制的数据目录；不直接写回用户源目录。
- 高频任务是继续编辑候选版本、查看测试进度、判断退化或失败，并在需要时展开原始证据。

## Capabilities and Constraints

- 已实现工作台创建、版本浏览与对比、测试用例生成、测试任务、测试报告等前端模块。
- 数据集模块尚未形成可操作能力，不应作为正常主导航入口展示。
- 本次只调整前端 UI/UX，不改变后端 API、数据模型、领域状态或计算口径。
- “任务运行成功”不等同于“Skill 验收通过”；界面必须保留事实与证据边界。
- 当前阶段不引入粒子、连线、背景动画或其他装饰性动效。

## Brand Commitments

- 产品名称固定为 SkillConsole。
- 气质为“田野实验室”：清澈、克制、可信、具有测量感并适合长期操作。
- 尺子是唯一显性的测量符号，可用于品牌图标与少量校准细节。
- 红色仅用于错误、失败和破坏性操作；黄色不作为页面或卡片主背景。

## Product Principles

1. 真实能力优先：已实现能力可进入，未实现能力不伪装成可用模块。
2. 结果先于证据：先回答状态、结果变化和下一步，再按需展开原始证据。
3. 单一主操作：每个页面或操作区域只突出一个最重要动作。
4. 语义一致：颜色只表达稳定语义，不用模块色制造额外认知负担。
5. 专业但自然：通过排版、留白和精确状态建立技术气质，不依赖装饰性“科技效果”。

## Accessibility & Inclusion

主要操作需支持键盘焦点、明确的状态文字和可辨识的错误恢复路径。颜色不得作为状态的唯一信息来源；正文和辅助文字需达到可读对比度。
